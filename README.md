# Intelligent Hybrid Retrieval Pipeline for 3GPP Telecom Documents


An intelligent retrieval pipeline for telecom (3GPP) specifications that combines
**dense (semantic) search + BM25 (sparse)** with **cross-encoder reranking**, and
rigorously **compares retrieval strategies** on quality, latency, statistical
significance, and ablations — on **real 3GPP documents** at scale.

The project is deliberately evaluated on **two query sets over the same real
corpus**, and the headline finding is that *the right strategy depends entirely
on the query distribution* — a conclusion that only becomes visible because both
are measured.

> All result tables below are transcribed from `results/metrics_*.csv` /
> `results/report_*.txt`, regenerated by `python run.py`.

---

## 1. TL;DR — the finding

| | Lexical queries (clause titles) | **Realistic queries (natural language)** |
|---|---|---|
| Best single retriever | BM25 ≈ Dense | **Dense — crushes BM25 (0.30 vs 0.08 nDCG@10)** |
| Does hybrid help? | Yes, small & significant (+0.06) | **No — naive hybrid *hurts*; optimal α = 1.0 (all dense)** |
| Does reranking help? | Hugely (+0.14) | Yes, but **capped by candidate recall** |
| Does the first stage matter after reranking? | No — washes out | **Yes — decisive** |

**The single most important result:** on lexically easy queries BM25 looks like a
strong baseline (nDCG@10 = 0.778) and hybrid+rerank is the story. On **realistic
natural-language queries, BM25 collapses to 0.082**, dense semantic retrieval
becomes dominant, and **naive hybrid fusion becomes actively harmful** because it
gives an almost-useless BM25 an equal vote. A retrieval evaluation that only used
the easy queries would have reached the *opposite* engineering recommendation.
This is the project's core contribution: measuring both, and being honest that the
naive conclusion doesn't survive a realistic query distribution.

## 2. The two benchmarks (same 5,267 real 3GPP chunks)

| Benchmark | Queries | Query = | Query↔gold token overlap | Character |
|---|---|---|---|---|
| `real` | 120 | clause **titles** (automatic) | **0.82** (median 0.89) | lexically easy, BM25-favoring |
| `real_nl` | 51 | hand-authored **information needs** | **0.40** (median 0.38) | realistic, vocabulary-mismatched |

Both use real 3GPP documents and automatic clause-based gold labels (see §6). The
`real_nl` questions are phrased the way a telecom engineer actually searches
("*How is a collision resolved when two devices pick the same random-access
preamble?*" → clause 38.321 §5.1.5), deliberately avoiding the clause-title
wording. The measured 0.40 vs 0.82 overlap confirms the realistic set removes the
lexical bias that inflates BM25.

## 3. Results — realistic natural-language benchmark (`real_nl`, 51 queries)

Dense = `BAAI/bge-small-en-v1.5` + FAISS-HNSW; reranker = `ms-marco-MiniLM-L6`.
Latency = per-query p50 (ms), warm, single-thread CPU (macOS arm64, 1 OMP thread).

| Strategy | nDCG@10 | Recall@10 | MRR | Lat p50 |
|---|---|---|---|---|
| BM25 (sparse) | 0.082 | 0.111 | 0.096 | 7 |
| **Dense (BGE)** | **0.297** | 0.350 | **0.351** | 7 |
| Hybrid RRF | 0.213 | 0.275 | 0.243 | 16 |
| Hybrid weighted | 0.237 | 0.297 | 0.282 | 17 |
| BM25 → CE | 0.228 | 0.268 | 0.278 | 237 |
| Dense → CE | **0.305** | **0.373** | 0.341 | 264 |
| Hybrid → CE | **0.305** | **0.373** | 0.339 | 268 |
| Hybrid → CE-TinyBERT | 0.249 | 0.301 | 0.297 | 70 |
| Hybrid → Lexical | 0.056 | 0.088 | 0.059 | 18 |

**Significance (paired bootstrap 95% CI + Wilcoxon, Holm-corrected across the family):**
- **Dense ≫ BM25**: +0.215 nDCG@10, CI [+0.134, +0.307], Holm p = 0.0002. 
- **Naive hybrid < Dense**: hybrid RRF (0.213) is *below* dense (0.297); the alpha
  ablation peaks at α = 1.0 (pure dense). Fusing in a near-useless BM25 hurts.
- **Reranking helps but is bounded**: `Dense→CE` = `Hybrid→CE` = 0.305; the
  difference between them is **not significant** (−0.001, p = 0.58) — *hybrid adds
  nothing over dense once you rerank*. `Hybrid→CE` beats `BM25→CE` significantly
  (+0.076, Holm p = 0.025) purely because BM25's candidates are worse.

## 4. Results — lexical clause-title benchmark (`real`, 120 queries)

| Strategy | nDCG@10 | Recall@10 | MRR | Lat p50 |
|---|---|---|---|---|
| BM25 (sparse) | 0.778 | 0.890 | 0.778 | 4 |
| Dense (BGE) | 0.767 | 0.868 | 0.807 | 8 |
| Hybrid RRF | 0.825 | 0.918 | 0.852 | 12 |
| Hybrid weighted | 0.835 | 0.918 | 0.864 | 13 |
| **BM25 → CE** | **0.921** | **0.972** | 0.917 | 432 |
| Dense → CE | 0.900 | 0.942 | 0.915 | 376 |
| Hybrid → CE | 0.913 | 0.961 | 0.915 | 421 |
| Hybrid → CE-TinyBERT | 0.874 | 0.929 | 0.888 | 69 |
| Hybrid → Lexical | 0.876 | 0.943 | 0.881 | 13 |

Here hybrid fusion is a small but **significant** first-stage win over BM25
(+0.057 nDCG@10, Holm p = 0.002), reranking is the big win, and — per the control
experiment — the three `→CE` variants are within ~0.02 of each other, so **the
first stage barely matters once you rerank** (here `BM25→CE` is even marginally
top). Exactly the naive conclusion §3 overturns for realistic queries.

## 5. Why the conclusions differ — the mechanism

Three diagnostics (in `report_*.txt`) explain the reversal:

**(a) Candidate recall @50 — the reranker's ceiling** (it cannot rank a passage it
never receives):

| First stage | `real` (titles) | `real_nl` (natural) |
|---|---|---|
| BM25 | 0.989 | **0.320** |
| Dense | 0.956 | 0.575 |
| Hybrid RRF | 0.969 | 0.542 |

On realistic queries **BM25 only surfaces 32% of gold in its top-50**, hard-capping
`BM25→CE`. On title queries every first stage is ~0.96–0.99, so the reranker has
full headroom and the first stage is interchangeable.

**(b) Rerank-depth sweep** (nDCG@10 vs #candidates the reranker sees): on `real_nl`,
`bm25_ce` climbs 0.075→0.263 with depth but never catches `dense_ce` (~0.30, flat)
— proof the first stage is decisive when candidate recall is low. On `real`, all
three converge by depth 20. See `results/rerank_depth_*.png`.

**(c) Dev/test protocol** (α selected on a disjoint dev split, reported on test —
rules out tuning on the test set): `real` selects α = 0.5 (test 0.832 = default);
`real_nl` selects α = 1.0 (test 0.319 > default 0.275). The headline tables use
**fixed defaults** (α = 0.5, RRF k = 60) that are *not* selected on the eval set.

## 6. Dataset — real 3GPP specifications, non-circular labels

`scripts/download_3gpp.py` downloads real specs as PDFs from **ETSI** (which
publishes 3GPP specs verbatim; Release 19): TS 38.331 (RRC), 38.300 (NR), 38.321
(MAC), 23.501 (5GC), 24.501 (NAS), 33.501 (Security). `data/build_real_corpus.py`
parses them (pypdf), strips ETSI page furniture, detects clause headings, and
chunks each clause → **5,267 passages**.

**Non-circularity.** Documents = actual 3GPP specs (not authored here). Gold =
chunks whose clause id matches the target clause — derived mechanically from the
document's own structure. For `real`, queries are the clause titles (automatic).
For `real_nl`, queries are hand-authored information needs judged against clauses
in documents the author did **not** write — standard test-collection practice.
Neither queries nor labels come from author-written *documents*.

## 7. Architecture

```
 query ─┬─ BM25 (rank_bm25) ─────────────┐ top-N
        └─ Dense (BGE-small + FAISS-HNSW)─┘ top-N
                      │ fuse: RRF / weighted (hybrid)
                      ▼ top-K candidates
             Rerank: CE-MiniLM-L6 / CE-TinyBERT-L2 / Lexical
                      ▼
                 final ranking
```

Controls `bm25_ce` / `dense_ce` (single first stage → same reranker) isolate
whether the hybrid stage earns its place. FAISS-HNSW is verified near-lossless
here (ANN vs exact top-10 recall = **0.996**); at 5k vectors flat search would
also suffice — HNSW is included to demonstrate the scale-ready path.

## 8. Rigor

- **Statistical significance**: paired bootstrap 95% CIs + Wilcoxon signed-rank,
  **two-sided** (CI-excludes-zero), with **Holm–Bonferroni** correction across the
  family of comparisons per metric.
- **Latency**: warm-up call before timing; mean/p50/p95 reported with the hardware
  and thread count (`report_*.txt` header), so numbers are interpretable.
- **Ablations**: fusion α, RRF k, and **rerank candidate depth**.
- **ANN correctness**: FAISS-HNSW recall vs exact reported.
- **Dev/test split** for hyper-parameter selection.
- **Error analysis**: `scripts/error_analysis.py` dumps failure cases and
  reranker lifts (`results/error_analysis_*.txt`).
- **Tests**: `pytest -q` — 13 tests (metrics, fusion, two-sided significance +
  Holm, torch-free smoke).

## 9. Quick start

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python scripts/download_3gpp.py       # one-time: fetch real specs (~34 MB)
python data/build_real_corpus.py      # parse -> corpus + title queries
python data/build_nl_queries.py       # natural-language query set

python run.py real_nl                 # realistic benchmark (headline)
python run.py real                    # lexical clause-title benchmark
python scripts/error_analysis.py real_nl
pytest -q
```

`run.py` auto-builds any missing data. Force the lightweight dense backend with
`python run.py real_nl lsa` (no torch needed; TF-IDF+SVD fallback).

## 10. Limitations & methodology notes

- **Silver labels.** Gold = chunks under the target clause: automatic and
  non-circular, but *topical* relevance, not adjudicated human judgment. Relevant
  passages may exist outside the labeled clause.
- **`real_nl` is small (51) and author-phrased.** Questions are hand-written (the
  documents are not), so query *phrasing* carries author style; a crowd-sourced
  query log would be the next step. CIs are correspondingly wider.
- **Absolute `real_nl` scores are low** (best nDCG@10 ≈ 0.31): finding 1–3 specific
  chunks among 5,267 from a paraphrase is genuinely hard; the *relative* ordering
  is the result, not the absolute level.
- **Single Release-19 snapshot, one domain.** No cross-dataset generalization
  claim. **HNSW at 5k vectors is not load-bearing** (flat is exact and sub-ms);
  it is present to show the scaling path.
- **Determinism**: fixed seeds for sampling and bootstrap; HNSW is approximate
  (measured recall 0.996), so dense ranks can vary negligibly.
